# Coach context preparation — test only

This branch does not update Build 78, main, the production API, or any OTA channel.

## Behavior

- After app-open interactions settle, wait 1.5 seconds and prepare reusable schedules, injury reports and team defense for the next two games per sport within 48 hours. A newly loaded schedule immediately discovers its context work.
- Start at most one context request at a time. Stop queuing after eight seconds per pass; revisit every two minutes while active. Backgrounding clears queued work. Starting Coach clears the queue immediately; overlapping Coach builds retain priority until both finish. A shared request already in flight can finish and serve Coach too.
- The existing authenticated `/api/prebuild/cron` additionally prepares authoritative player history for up to 16 athletes per sport, with at most two history requests per sport in flight. It prioritizes confirmed-out players on upcoming teams, whose missing workload can otherwise have no posted prop. Concurrent cron runs coalesce.
- Server preparation works while phones are closed. iOS background execution is not required. No tickets or new simulations are generated by the new warmer. Existing server odds/props caches retain their normal short TTLs; mobile preparation does not cache odds or props. Final pick qualification and odds retrieval still run on demand.
- Roster positions flow through the existing roster lookup into both HTTP and in-process simulations. A roster role is not a confirmed starting lineup.
- The shared simulation runner rejects players marked out by the loaded injury report before any distribution-cache read or history fetch. Both sides are unavailable. Questionable/doubtful statuses are not treated as confirmed absences.
- Workload derives from actual available stat labels. Targets are not routes, rebounds are not rebound chances, and fixed carry fractions are not measured red-zone use. Missing measurements stay missing. Existing capped, low-confidence fallback behavior remains available; no confirmed starters are invented.
- History freshness is measured from the source fetch, including shared-cache reads; reading it cannot extend its original 30-minute lifetime. Source fetches have a five-second timeout.

## Isolated server setup

The current preview OTA configuration points to the production API. Do not deploy this backend branch there for testing. Deploy it to a separate test backend first and set that server's `PREBUILD_CRON_KEY`. From an external scheduler, run `node scripts/warm-coach-test-context.mjs` every five minutes with `COACH_TEST_API_URL` and `COACH_TEST_PREBUILD_KEY`. The script has no default destination and rejects the known production hosts. Point the test app at that isolated backend; do not change the production app environment.

This script is prepared, not scheduled or activated by this PR. Until an isolated backend is configured, API and app verification is local. Preparation is best-effort and process/shared-cache dependent; live provider availability, lineup confirmation, and device response times are not guaranteed by local tests.
