# Basketball double-double and triple-double props

Coach and Simulator consume `player_double_double` and `player_triple_double` in the existing event prop request, using the existing athlete-history prefetch, simulation batch, cache, concurrency and deadlines. No new network phase, dedicated endpoint, background warmer or separate market fetch is added. The provider lists both as Yes/No basketball markets: https://the-odds-api.com/sports-odds-data/betting-markets.html#nba-ncaab-wnba-player-props-api. Actual bookmaker availability is required.

Both sides retain their posted sportsbook prices. A missing provider point on a known binary market maps to the settlement threshold 0.5; ordinary missing numeric lines remain unavailable. Simulator exposes separate Double-Double and Triple-Double filters and displays Yes/No selections. Coach locks explicit milestone requests to the named market(s), retains that constraint on new-ticket follow-ups, and reports shortages through the existing quality gates. Existing 52% / C+ and exact-market 10k provenance requirements remain in force.

Game-log mapping counts categories at 10+ among PTS, REB, AST, STL and BLK within the same game: at least two for a double-double, three for a triple-double. Missing or ambiguous categories stay unavailable. Do not estimate a joint milestone by multiplying marginal points/rebounds/assists probabilities.

The server draws Bernoulli 0/1 outcomes from weighted observed milestone frequencies (40% last five, 30% last ten, 30% available history), each smoothed with Beta(1,1). At least three complete games are required. Generic count-stat pace, minutes, venue and injury multipliers do not modify this probability. The model is a historical-frequency estimate, not a calibrated joint player-stat model; 10,000 draws quantify the specified model and do not establish predictive accuracy. Existing empirical local fallbacks retain zero simulation provenance and cannot satisfy Coach's exact-market 10k gate.

Yes and No score the same 10,000 draws. Milestone distribution keys include a model version to prevent reuse of older count/normal double-double draws; ordinary markets retain warm keys. On the development host, 100 repetitions of each complete 10k two-side draw/scoring pass averaged about 4.2ms for double-doubles and 2.7ms for triple-doubles. This is CPU-only timing, not a phone delivery-time guarantee. A mocked Coach event load confirms both markets use one request, and the raw-log integration test verifies complete 10k outputs for both sides. Release-critical tests include the new milestone contracts.

Release requires the API deployment and the reviewed production OTA for mobile changes. No native dependencies or runtime changes are introduced.
