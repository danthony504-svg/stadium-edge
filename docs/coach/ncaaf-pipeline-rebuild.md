# NCAAF pipeline rebuild: operational stages and model lifecycle

Before this rebuild the collection workflow was not a production release pipeline. It recorded a basic research candidate, while availability/opponent/venue development was separate and neither a fitted adjusted trainer nor an approved model-to-Coach handoff was registered. A subsequent phase implements the research trainer and journal; see `ncaaf-adjusted-research-model.md`. No actual model is declared fitted until authentic development data passes its fit guards. Accumulating old forecasts could not make those missing components appear. This rebuild explicitly distinguishes operational task completion, authenticated development examples, prospective model protocol and independent release approval.

## Implemented operational changes

The background worker now runs an independent lifecycle coordinator, outside Coach requests. Settlement, label maintenance, development preparation and research metrics run before potentially slow collection; a settlement-only mode avoids entering any collection phase. Phase claims and progress are durable, including during a worker termination. It uses a dedicated advisory lock and durable stage records. The existing collection/settlement workflow retains its locks, paid-odds limits, source identity checks and immutable forecasts. Missing odds credentials skip collection before any slot/paid-request claim, while cached outcome maintenance continues; restoring credentials can collect in the same slot. A failure or completed collection slot cannot prevent the independent OT research journal, label maintenance, development preparation or descriptive metrics refresh.

Label maintenance runs at most once per 30 minutes, with a claim written before work even on failure. `ncaaf-context-dataset.mjs --labels-only --execute` bypasses collection/source assembly and processes cached settlements only. It has a separate status and cursor, preserving collection reports. No network request or paid odds call is added by labeling or development preparation. Metrics queries project only the required score fields rather than loading thousands of raw final summaries into worker memory. The existing notification cron triggers background work every 15 minutes; the existing collection slots remain unchanged.

`ncaaf-prepare-development.mjs --execute` reads at most 1,024 v2 inputs and their exact immutable labels. It rederives conference availability, event identity and participation features from the original archived sources at the original cutoff, authenticates the final summary and source history, verifies the exact input/label hashes, rejects future/target-game history, and deduplicates season/event identities. Unknown usage or venue stays unknown; no impact coefficients or healthy-player assumptions are created. The prepared manifest contains references and hashes, not athlete rows. It is content-addressed, development-only and not holdout evidence. Above the batch limit preparation fails explicitly and requires partitioning rather than silently dropping examples.

A frozen protocol helper fixes model hash, implementation commit, training-game exclusion list, feature version, exact full-game markets, 10,000 simulations and the existing 500-game/two-season requirements. Holdout guards reject training reuse, changed model/protocol hashes, forecasts before the model freeze, late writes, development relabeling and lower simulation counts. These helpers do not themselves certify a trained model, authorize production or register a live model. They are the boundaries the future adjusted trainer/journal must use.

`/api/research/ncaaf/status` provides sanitized live inventory, task status and explicit model/release blockers; it is linked from the research preview. Counts are descriptive research counts, not qualified independent holdout counts. Unknown qualification remains null rather than being presented as passed. Reads are bounded/coalesced/cached and make no provider calls. The research trainer and journal now run as separate worker stages, waiting on sufficient verified development data and a frozen candidate respectively. Independent holdout evaluation and Coach integration remain unapproved; successful collection or fitting is never labelled model validation.

## Still required for a full Coach rebuild and release

1. Obtain completed, authenticated development examples with adequate signal variation.
2. Fit and review the implemented experimental adjusted model using sufficient finalized examples. Its predeclared 23-game development guard and signal-variation checks are fitting guards, not acceptance evidence. No penalty or coefficient is invented in the absence of data.
3. Freeze that actual model artifact and register its prospective protocol, including every training/source game that must be excluded from holdout.
4. The separately versioned research journal is implemented and waits for a frozen artifact and post-freeze contexts. Verify its actual recorded forecasts; preserve prior research predictions and keep development inputs excluded from the holdout.
5. Score independent qualifying forecasts against authentic outcomes/market baselines and complete calibration, conservative missing-data, opponent/venue, OT and source reviews.
6. Meet the existing 500-game/two-season acceptance requirement. A newly created model cannot fabricate prior-season forecasts; this remains a calendar/evidence constraint, not a deployment task.
7. Register the approved artifact in server inference and coordinate the corresponding mobile gate/configuration change, run Coach regressions and controlled rollout, then monitor. Mobile code changes require an OTA; no new native build is authorized here.

No Coach gate, grade/confidence floor, subscription rule, football-period restriction or accepted model registry entry is changed by this operational rebuild. This is not a full unlock, an assertion of an actual fitted model, or validation evidence. Remaining work above must not be reported as completed.

## Verification

Focused tests cover failure isolation, durable retry cadence, overlap/database guards, exact input/final/history binding, unknown features, plan-only labeling, hash-stable model protocols, training/holdout leakage and unchanged release thresholds. API typecheck/build and full API regressions run before deployment. Live verification checks the new coordinator/status, preservation of the original forecast fingerprint and unchanged Coach gate.

## Daily scoreboard request coverage (2026-10-24)

The production archive for October 24 contained only 25 ESPN events, ending at 19:45Z, and excluded 20 provider events for absent exact identities. Live read-only checks reproduced 25 events with `limit=1000`, while `limit=100` and `limit=200` returned 44 events through 02:15Z the following UTC day. This is observed endpoint behavior, not a claim about an officially documented ESPN limit. The live collector, history collector and settlement utility now request the working bounded `limit=100` URL. Identity, kickoff, provenance, freshness and immutability checks remain intact. No extra paid odds request is added. Fresh production coverage must be checked after the next scheduled capture; this change alone does not establish new development games or model eligibility.

The first-write readiness guard now applies to new development contexts as well as holdout contexts. Freshly discovered targets without complete observed usage/eligible history are withheld without consuming their immutable key. Later collection can prewarm the new slate and retry; existing archived contexts are preserved. New matched events are not counted as eligible development examples until all evidence checks pass.

## Newly discovered target catch-up

A separate, cadence-limited lifecycle stage now catches up development evidence from the latest captured slate between paid odds slots. It runs only before a frozen adjusted candidate exists, requires a current pregame slate, and reuses the existing slot's immutable history caches and 64-attempt usage ledger. It repairs team history, fills observed usage, then retries context assembly. It does not request odds or overwrite existing contexts/forecasts. A stage failure is isolated and reported; collectors retain their existing timeouts/budgets. After model freeze it skips, preserving the prospective holdout path and quote-freshness ordering.

The collection pipeline now reloads both the archive and its matched target list after fresh capture. Forecast processing and `matchedEvents` therefore describe the newly captured slate, rather than cached prewarming targets. Production observation motivating this fix: the 9 AM October 24 archive contained 45 matched events/44 daily scoreboard events, while the old summary still reported 29 cached targets. Context assembly added two genuine records (16→18), withholding five additional contexts for incomplete usage rather than consuming their immutable keys.

The Big Ten public feed began emitting `postedTime: "9:00:00"` on October 24. Publication parsing now accepts one- or two-digit hours, normalizes padding, and retains explicit hour/minute/second, timezone, receipt and future-publication checks. Development catch-up performs one separately deduplicated public conference capture per odds slot using `--development-catchup`; each pass remains bounded to eight public calls, so initial plus catch-up is at most sixteen public conference calls per odds slot. This permits an initial failed report capture to recover without an unbounded retry loop or another paid odds request.
